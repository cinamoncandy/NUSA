## 1. 목적과 바뀌지 않는 것
지금까지 대화형 개발, 자동 코딩, PR 리뷰의 중심은 ChatGPT/Codex였습니다. 앞으로는 **Claude를 중심으로** 운영합니다.

**절대 바뀌지 않는 것**
- PAPER_ONLY, `liveAuthority=NONE`, `productionMutationAllowed=false`, `aiAuthority=ZERO_AUTHORITY`. 자본·위험·임계값 완화 금지(연속 손실 한도 3 유지).
- "규칙이 결정하고 AI는 고친다": 분류, 권한, 재시도 예산, 병합은 결정적 규칙이 정합니다.
- 병합은 결정적 Audit를 통과한 뒤 릴리스 봇(`nusa-release-authority[bot]`)만 합니다. AI는 자기 PR을 승인·병합하지 않고, GitHub의 "승인(Approve)"도 누르지 않습니다.
- 역할 이름은 헌장(`docs/NUSA_GOVERNING_CHARTER.md` §1)의 OWNER → CORE → EVOLVE → AUTOPILOT / VALIDATOR / RESEARCH를 그대로 씁니다. 바뀌는 것은 각 자리에 앉는 AI뿐입니다.
- AIPOS와 작업지시서는 특정 AI 이름에 묶이지 않습니다(`.aipos/AI_HANDOFF_CONTRACT.md`의 AI-Agnostic Execution Rule). `CLAUDE.md`는 `AGENTS.md`를 가리키는 보조 문서로 남습니다.
- 소유자 단축어(`ㅇ`, `ㅂ`, `ㅎ`, `ㅈ`, `/grill-me`)는 Claude에서도 그대로 씁니다.

## 3. 확인된 문제 (재설계가 풀어야 할 것)
1. **알림 폭주는 Codex만의 문제가 아닙니다.** 10-12(UTC) 하루에 `Autopilot Execution Consumer`가 230번 실패했습니다(10-11은 26번).
   - Worker의 정기 실행은 main 최신 커밋에서 **어떤 실패 실행이든**(repository_dispatch만 빼고, 24시간 안) "고칠 실패"로 잡습니다(`apps/autopilot/src/scheduledRuntime.ts:216`, 24시간은 `:55`).
   - 그래서 Codex 코딩 실패(run 38300571241)를 19:55~20:48 UTC에 약 5분 간격으로 11번 다시 보냈습니다. 멈춘 것도 실패별 상한 때문이 아니라 진행 중 작업 한도(`WIP_LIMIT_REACHED`)와 main 변경 때문이었습니다.
   - Codex가 아닌 PAPER 증거 워크플로의 실패(run 38287517884)도 같은 경로의 대상이었습니다.
   - 저장소 이름이 Dokkebi였던 동안에는 모든 실행이 `repository mismatch`로 실패했습니다(예: run 38268963342).
   - 실행 소비자는 결과가 `FAILED_CLOSED`이면 실패로 끝납니다(`scripts/autopilot-dispatch-retry.js:1337`). 실행을 일으킨 계정이 `cinamoncandy`여서 실패 알림이 소유자에게 갑니다. GitHub 문서상 실행을 일으킨 사용자가 완료 알림을 받습니다(알림 설정을 켠 경우).
   - Codex 워크플로를 끈 뒤에도 22:06과 22:11 UTC에 2번 더 실패했습니다(로그에 사유 없음). Codex를 꺼도 이 구조는 그대로 남습니다.
2. **소유자 활동 게이트(#2644, 보류 중)를 지금 켜면 안 됩니다.**
   - 게이트가 닫히면 `OWNER_ACTIVE`를 `FAILED_CLOSED`(STOP)로 돌려주는데, 실행 소비자는 이것을 실패로 끝냅니다(`scripts/autopilot-dispatch-retry.js:1059-1063`, `:1337`). 그러면 소유자가 일하는 동안 디스패치가 있을 때마다 빨간 실행과 알림이 생길 수 있습니다.
   - Worker 토큰이 소유자 계정이어서, 오토파일럿 자신의 활동도 "소유자 활동"으로 보입니다.
3. **같은 범위의 중복 작업**: #2585(Claude, 실패 분류기)에는 "정식 작업, 중복 구현 금지" 댓글이 `cinamoncandy` 이름으로 달렸습니다(사람인지 AI인지는 구별할 수 없음). 그런데도 다른 브랜치에서 같은 분류 내용을 현재 main 위에 다시 구현한 #2596이 병합됐고, #2585는 병합되지 않은 채 닫혔습니다.
4. **state.yaml 충돌**: PR마다 `state.yaml` 끝에 항목을 덧붙이기 때문에 같은 세션의 PR끼리도 충돌합니다(#2649가 병합되자 이 PR #2650이 충돌). 두 Claude가 동시에 일하면 더 자주 생깁니다.
5. **인수인계 경로가 고정됨**: `CLAUDE.md`가 날짜가 박힌 인수인계 파일 하나(`2026-10-12-claude-handoff.md`)를 가리킵니다. 두 계정이 같은 파일을 고치면 충돌하고, 날이 바뀌면 낡은 파일이 됩니다.
6. **헷갈리는 지침 문구**: 마스터 지침 §1과 §14는 조건이 맞으면 CORE가 "병합할 수 있다"고 씁니다. 실제로는 main 보호와 소유자 규칙에 따라 릴리스 봇만 병합합니다.
7. **리뷰 공백**: Codex 리뷰가 멈춰서 지금은 자동 리뷰가 사실상 없습니다.

**독립성 규칙 (2판에서 고침)**
- 코드나 워크플로를 바꾸는 PR은 **작성하지 않은 쪽**이 새 세션에서 `docs/GRILL_ME_PROTOCOL.md`대로 리뷰합니다. 메인이 쓴 PR은 보조가, 보조가 쓴 PR은 메인이 봅니다. 같은 쪽의 다른 세션이 대신할 수 없습니다.
- 문서와 AIPOS 기록만 바꾸는 PR(`authority_impact: none`)은 `AGENTS.md`의 가벼운 경로대로 결정적 Audit만 거칩니다.
- 막아야 하는 지적(P0/P1)은 **인라인 리뷰 스레드**로 남깁니다. 스레드가 해결되기 전까지 Release가 병합하지 않습니다(§2). 나머지 지적은 리뷰 1건에 묶은 요약으로 남겨 알림이 한 번만 가게 합니다.
- 두 Claude는 같은 계열의 모델이라 같은 실수를 함께 놓칠 수 있습니다. 그래서 리뷰는 판정이 아니며, CI와 결정적 Audit를 대신하지 않습니다.
- GitHub 계정을 나누는 것은 독립성의 조건이 아닙니다. 누가 했는지 구별하고 게이트를 켜기 위해 필요합니다(§5).

## 5. 신원과 계정 (P0, 소유자 작업)
- **약관 제한**: GitHub 약관상 한 사람은 무료 개인 계정 1개와, **자동 작업에만** 쓰는 무료 머신 계정 1개까지 가질 수 있습니다. 사람이 머신 계정으로 직접 작업하면 안 됩니다. GitHub 앱(릴리스 봇과 같은 방식)은 사람 계정이 아니라 앱 설치로 동작합니다.
- **권장 배치**
  - `cinamoncandy`(개인 계정): 소유자와 메인 Claude가 씁니다. 소유자 활동 게이트가 지켜보는 계정입니다.
  - 머신 계정 1개(새로 만듦): 보조 Claude만 씁니다. 저장소에 쓰기 권한(관리자 아님) 협업자로 추가하고, 보조 Claude 계정의 GitHub 연결을 이 계정으로 바꿉니다.
  - Worker 토큰(`NUSA_GITHUB_TOKEN`): 소유자 토큰 대신 **새 GitHub 앱의 설치 토큰**(권장)이나 머신 계정 토큰을 씁니다. 그러면 실패 알림이 소유자에게 가지 않고, 게이트가 오토파일럿의 활동을 소유자 활동으로 착각하지 않습니다. 이 앱은 릴리스 권한 앱과 **반드시 다른 앱**이어야 합니다. 같은 앱을 쓰면 Worker가 `nusa/release-authorized`를 쓸 수 있게 되어 권한이 넓어집니다.
  - Codex 러너를 계속 쓴다면, 그것도 소유자 계정이 아닌 신원으로 둡니다.
- 계정을 나누기 전에도 구별할 수 있도록 커밋 꼬리말에 `NUSA-Agent-Role: main|assistant`를 남깁니다.
- 이 세션이 확인할 수 없는 것: 협업자 목록, 보호 규칙의 리뷰·푸시 제한 항목, Worker 토큰의 종류(실행자가 `cinamoncandy`라는 것만 확인).

## 6. 작업 흐름
1. **역할 알기**: 각 Claude 환경(클라우드 환경 설정이나 로컬 설정)에 `NUSA_AGENT_ROLE=main` 또는 `assistant`를 둡니다. 값이 없으면 보조로 보고, 읽기와 검증부터 합니다.
2. **작업 선점 (2판에서 고침)**: 1판의 `state.yaml` `claimed_by` 대신, 작업을 시작할 때 작업지시서 ID가 들어간 **브랜치를 먼저 push**합니다. PR은 아직 열지 않습니다.
   - 저장소의 push 트리거는 main과 특정 `agent/*` 브랜치에만 걸려 있습니다. 그래서 이 push로는 워크플로가 돌지 않아 비용과 알림이 없습니다(`agent/` 접두어는 쓰지 않음).
   - 시작하기 전에 열린 PR과 같은 ID의 브랜치를 검색합니다. 이미 있으면 손대지 않고 소유자에게 알립니다.
   - `state.yaml`은 병합되기 전에는 다른 쪽에 보이지 않고 충돌도 잦아서, 선점 수단으로 맞지 않습니다.
3. **크기 배분**: 150줄·파일 1개 이하이고 허용된 CI 실패를 고치는 일은 오토파일럿이 합니다. 설계가 필요하거나 큰 일은 메인, 검증·조사·기록·소형 수정은 보조가 맡습니다.
4. **검증 순서**: 로컬 검증 → PR → 정확한 head의 CI → (코드 PR이면) 비작성자 리뷰 → 결정적 Audit → 릴리스 봇 병합.
   - **코드 PR은 초안(draft)으로 엽니다.** CI가 통과하면 Audit와 Release가 몇 분 안에 자동으로 병합할 수 있는데(#2649는 열린 지 7분, #2643은 8분 만에 병합), 결정적 Audit는 초안과 `HOLD` PR을 건너뜁니다(§2). 그래서 초안으로 열어야 리뷰보다 병합이 먼저 일어나지 않습니다. 리뷰 지적을 고친 뒤 작성자가 "준비 완료(Ready for review)"로 바꿉니다.
   - 배포 대상이면 보조가 상시 승인 범위에서 `oracle-paper-release.yml`을 정확한 main SHA로 실행합니다. 이 실행은 한 곳에서만 합니다.
5. **기록**:
   - 인수인계는 역할별 파일 `.aipos/handoffs/<날짜>-<main|assistant>.md`로 나눕니다. `CLAUDE.md`는 고정 파일 대신 "가장 최근 날짜의 인수인계 파일"을 읽으라고 안내합니다.
   - `state.yaml` 충돌은 당분간 병합으로 풉니다. 너무 잦아지면 항목별 파일로 나누는 일을 따로 검토합니다(검증기 변경이 필요).

## 7. 오토파일럿에서 바꿀 점 (P1, 코드 작업지시서 1개)
1. **수리 대상 허용 목록**: main의 정식 CI(`.github/workflows/ci.yml`) 실패와 따로 허용한 워크플로만 수리 대상으로 삼습니다. 오토파일럿, Codex, 이벤트 브리지, Audit/Release 같은 제어 워크플로의 실패는 대상이 아닙니다.
2. **실패 1건당 시도 상한**: 같은 실행 ID에 대한 수리 시도 횟수를 실행 조정자(Durable Object)에 남깁니다. 상한(예: 3번, 재시작해도 유지)을 넘으면 기록 1건만 남기고 멈춥니다.
3. **예상된 멈춤은 조용히**: 게이트 닫힘, 공급자 대기, 저장소 불일치처럼 고칠 수 없는 멈춤은 실행 소비자를 실패로 끝내지 않습니다(`NO_ACTION`). 가능하면 디스패치 전에 판단해서 실행 자체를 만들지 않습니다.
4. **신원 분리**: Worker 토큰을 소유자 계정에서 떼어 냅니다(§5).

이 밖의 원칙:
- 1~4가 끝나기 전에는 Codex 코딩을 다시 켜지 않고, 소유자 활동 게이트도 켜지 않습니다.
- **엔진**: Workers AI(무료)를 유지합니다. Claude를 오토파일럿 엔진으로 쓰는 것은 유료 API 결정이라, 예산과 상한이 승인되기 전에는 하지 않습니다(결정 3).
- 크기 한도(150줄, 파일 1개)를 유지합니다. 완료 영수증(#2637~#2639)이 들어오기 전까지 `AUTOPILOT_VERIFIED_COMPLETION_LOOP=false`입니다.

## 8. 리뷰와 알림
- **리뷰 교체**: Codex 리뷰 봇 대신, 작성자가 아닌 Claude가 `/grill-me`로 리뷰합니다. 기본은 소유자나 상대 역할이 요청할 때입니다.
- 모든 PR에 자동으로 리뷰를 돌리는 방법도 있습니다(Claude Code GitHub Actions, 또는 Claude Code Review). 다만 저장소 비밀값(API 키나 구독 토큰 `CLAUDE_CODE_OAUTH_TOKEN`), 사용량, Claude GitHub 앱의 넓은 권한이 필요해서 따로 결정합니다(결정 6).
- **알림 줄이기**:
  1. §7의 1~3번을 적용합니다.
  2. Worker 신원을 분리해서 실패 알림이 소유자에게 가지 않게 합니다.
  3. Codex 리뷰 봇을 이 저장소에서 끕니다(한도 댓글 중단).
  4. 리뷰는 1건으로 묶습니다.
  5. 세션 보고는 조치가 필요할 때만 짧게 합니다.
