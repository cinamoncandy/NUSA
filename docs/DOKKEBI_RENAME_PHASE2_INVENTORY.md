# Dokkebi 이름 변경 2단계: 영향 목록과 이전 계획 (설계 제안)

상태: **설계 제안**. 코드·설정·권한 변경 없음 (`authority_impact: none`). 이 문서는 실행을 승인하지 않습니다. 각 항목은 소유자 결정 뒤 별도 작업지시서로 진행합니다.
숫자는 2026-10-12 main(`git grep`) 기준 측정값이며 이후 달라질 수 있습니다.

## 1. 결정된 이름 (소유자 2026-10-12)
| 대상 | 새 이름 | 영문 표기 |
|---|---|---|
| 제품(NUSA) | Dokkebi | `Dokkebi` / 식별자는 소문자 `dokkebi` |
| AIPOS | 도깨비터 | `Dokkebiteo` / 식별자는 소문자 `dokkebiteo` |

1단계(사용자에게 보이는 글자)는 PR #2645에서 제품 이름 `Dokkebi`로 진행했습니다. 소유자는 **내부 식별자까지** 바꾸기로 했고, AIPOS 이름을 도깨비터로 하기로 했습니다.
아직 정해지지 않은 것: AIPOS는 **표시 이름만** 바꿀지, `.aipos/` 폴더와 도구 이름까지 바꿀지(§4).

## 2. 규모 (측정값)
- 이름이 들어간 파일 약 1,350개: 작업지시서 356, `apps/desktop` 104, `apps/mobile` 101, `apps/autopilot` 75, `apps/cloud` 67, 감사 문서 46, 워크플로 30, 결정 기록 16.
- `NUSA_*` 환경 변수 304종, `EXPO_PUBLIC_NUSA_*` 3종. 파일·폴더 이름에 `nusa`가 들어간 것 약 120개(예: `NUSA_CONSTITUTION.md`, `.github/hooks/nusa-safety.json`, 로고 SVG, `nusa*.ts`).
- 외부에 노출된 이름: 거래 서버 `nusa-api.duckdns.org`(9곳), 오토파일럿 Worker `nusa-autopilot.desporin12.workers.dev`(16곳), 필수 검사 `nusa/release-authorized`(7곳), 릴리스 봇 `nusa-release-authority`, 안드로이드 `com.nusa.mobile`, 데스크톱 `com.nusa.trader`, `productName: NUSA`, 패키지 이름 `nusa`.
- AIPOS: `.aipos/` 아래 518개 파일, AIPOS를 언급한 파일 약 308개, `AGENTS.md`·`CLAUDE.md`·검증 도구·`state.yaml`이 이 이름에 기대고 있습니다.

## 3. 항목별 처분 (기본 제안)
위험은 "바꾸다 틀리면 무엇이 멈추는가"입니다.

| 묶음 | 예 | 위험 | 제안 처분 |
|---|---|---|---|
| A. 표시 이름 | 화면 글자, 문서 설명, 창 제목 | 낮음 | **완료**(#2645). 남은 문서는 점진적으로. |
| B. 코드 안 이름 | 클래스·타입(`NUSAApi`), 전역(`window.NUSA*`), 변수 | 중간 | 기계적 리팩터링. 한 묶음씩 테스트와 함께 별도 PR. 프로토콜 문자열(`app: "NUSA"` 모바일 브리지)은 호환 때문에 **병행 수용** 후 교체. |
| C. 파일·폴더 이름 | `nusa*.ts`, 로고 SVG, 훅 JSON | 중간 | 이동(rename)으로 이력 보존. 참조하는 테스트·워크플로·`.aipos` 경로를 같은 PR에서 함께 수정. |
| D. 환경 변수 | `NUSA_*` 304종 | **높음** | 코드는 새 이름(`DOKKEBI_*`)을 먼저 읽고 옛 이름을 폴백으로 읽는 **병행 기간**을 둔 뒤, 배포 설정을 옮기고, 마지막에 옛 이름을 제거. 한 번에 바꾸면 배포가 설정을 못 찾아 멈춤. |
| E. 필수 검사·릴리스 봇 | `nusa/release-authorized`, `nusa-release-authority` | **매우 높음** | 새 이름의 검사를 **병행으로 추가**하고, 소유자가 main 보호 규칙에 새 검사를 필수로 추가하고, 봇 앱 이름 변경 또는 신규 앱 등록은 소유자가 직접. 모든 PR이 새 검사를 받는 것을 확인한 뒤에만 옛 검사 제거. 제가 보호 규칙을 바꿀 수 없습니다. |
| F. 서버·Worker 주소 | `nusa-api.duckdns.org`, `nusa-autopilot.*.workers.dev` | **높음** | 새 이름을 병행 등록(DNS·Worker 신규 이름)하고 클라이언트가 두 주소를 모두 받게 한 뒤 전환. 모바일 앱은 이미 설치된 버전이 옛 주소를 쓰므로 **옛 주소를 오래 유지**. 새 도메인·계정은 소유자 규칙("새 계정 안 만든다") 확인 필요. |
| G. 앱 식별자 | `com.nusa.mobile`, `com.nusa.trader`, `productName` | **매우 높음** | **바꾸지 않는 것을 기본값으로 제안.** 안드로이드 패키지 ID가 바뀌면 다른 앱이라 기존 설치가 업데이트되지 않고 보안 저장소와 키가 사라집니다. `productName`은 Electron 사용자 데이터 폴더를 정해 로컬 데이터를 못 찾게 될 수 있습니다. 바꾸려면 별도의 데이터 이전 설계가 먼저 필요. |
| H. 헌장·감사 문서 | `NUSA_CONSTITUTION.md`, `docs/audits/*`, `.aipos/decisions/*` | 높음(의미) | 과거 기록은 **수정하지 않음**(역사적 증거). 필요하면 상단에 "현재 이름은 Dokkebi" 주석만 추가. 헌장 파일 이름 변경은 소유자 결정. |
| I. 작업지시서·상태 | `.aipos/work-orders/WO-*` 356개 | 중간 | 과거 작업지시서의 이름은 **바꾸지 않음**(ID는 영구 참조). 새 문서부터 새 이름. |

## 4. AIPOS → 도깨비터(Dokkebiteo)
- **표시 이름**: 문서와 설명에서 "AIPOS(도깨비터)"로 병기하는 것은 쉽고 위험이 낮습니다.
- **식별자까지**: `.aipos/` 폴더, `AGENTS.md`의 복구 절차, `scripts/validate-aipos-yaml.js`, `.aipos/aipos.yaml` 키, 작업지시서 인덱스 도구가 모두 이름에 기대고 있습니다. 새 세션이 복구하는 규칙이므로 틀리면 복구 자체가 실패합니다.
- **제안**: 표시 이름만 먼저 바꾸고(병기), 폴더·도구 이름은 **마지막 단계**에서 `.dokkebiteo/`를 병행으로 만들고(심볼릭 호환이 불가한 환경이 있으므로 복사 후 검증) 도구가 두 경로를 모두 읽게 한 뒤 전환합니다. 소유자가 폴더 이름까지 원하는지 먼저 확인해야 합니다.

## 5. 이전 순서 (제안)
1. 결정 확정(§6) → 2. 표시 이름 남은 부분(A, 문서 병기) → 3. 코드 안 이름과 파일 이름(B, C) 묶음별 PR →
4. 환경 변수 병행 읽기 도입(D 1단계) → 5. 필수 검사·봇·주소를 새 이름 **병행** 도입(E, F; 소유자 작업 포함) →
6. 모든 소비자가 새 이름으로 확인된 뒤 옛 이름 제거(D, E, F 마지막 단계) → 7. G는 별도 결정.
각 단계는 **되돌릴 수 있어야** 하며, 옛 이름 제거 단계만 되돌리기 어렵습니다. 그 단계 전에는 병행 상태에서 CI·배포·릴리스가 모두 통과한 증거가 있어야 합니다.

## 6. 소유자 결정 항목
1. AIPOS는 표시 이름만(권장) 바꿀지, `.aipos/` 폴더와 도구 이름까지 바꿀지.
2. 안드로이드 `com.nusa.mobile`, 데스크톱 `com.nusa.trader`, `productName`은 **유지**(권장)할지.
3. 서버와 Worker 주소를 새 이름으로 옮길지(새 도메인이나 계정이 필요할 수 있음), 옛 주소는 얼마나 유지할지.
4. 필수 검사와 릴리스 봇을 새 이름으로 병행 도입할지(소유자가 보호 규칙과 앱 설정을 직접 바꿔야 함).
5. 과거 헌장·감사 문서·작업지시서는 수정하지 않는다는 원칙에 동의하는지.

## 7. 하지 않는 것과 한계
- 이 문서는 어떤 이름도 바꾸지 않습니다. 목록의 숫자는 측정값이며, 일부 항목은 코드로 일일이 확인하지 못했습니다(예: 외부 서비스 설정에 남은 이름).
- 외부 서비스(GitHub 앱 설정, Cloudflare, DNS, 앱 스토어·배포 채널)의 이름은 저장소에 없어서 이 목록에 없을 수 있습니다. 소유자가 직접 확인해야 합니다.
