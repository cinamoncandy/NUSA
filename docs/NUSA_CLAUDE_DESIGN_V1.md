# NUSA 설계 v1 (Claude 설계, 2026-10-14)

상태: **채택(ACCEPTED), 2026-10-14**. 소유자가 "다 추천대로"라고 답했습니다(§7). 소유자가 "지금까지는 ChatGPT가 설계했으니 이번에는 Claude가 마음대로 다 해 보라"고 했고, 바이낸스 선물을 추가하라고 했습니다(2026-10-14 대화). 이 문서는 설계만 하고 아무것도 바꾸지 않습니다(`authority_impact: none`). 각 단계는 작업지시서 하나, PR 하나로 나눠 진행하고, 표시한 항목은 소유자 승인 뒤에만 시작합니다.

근거: 저장소를 읽어 확인한 사실입니다(파일 위치는 각 절에 적었습니다). 운영 서버와 Worker의 `/health`는 이 세션의 네트워크 정책 때문에 열리지 않아(403) 확인하지 못했습니다. 다음 세션은 다시 확인해야 합니다.

## 0. 바뀌지 않는 것
- PAPER_ONLY, `liveAuthority=NONE`, `productionMutationAllowed=false`, `aiAuthority=ZERO_AUTHORITY`.
- 연속 손실 한도 3, 일일 손실·노출 한도, 자본, 자격 기준은 낮추지 않습니다. 손실 초기화, 앞당긴 자격 부여, 꾸며 낸 Research 계보도 하지 않습니다.
- 병합은 결정적 Audit와 릴리스 봇(또는 소유자)만 합니다.
- 바이낸스 선물도 **PAPER 전용**입니다. API 키, 실주문, 실거래 경로는 이 설계에 없습니다.

## 2. 설계 A: 수익 엔진 (연구 → 후보 → PAPER)
**원칙**: 1분봉 단타는 수수료 때문에 그만둡니다. 증거가 있는 쪽(일봉·4시간봉, 장세 필터)으로 옮기고, 한 번에 하나의 가설만 미리 등록해서 검증합니다.

A1. **연구 대상 바꾸기** (소유자 승인 필요: 연구 방향)
- 런타임 연구 그리드(`researchExperimentComposition.ts:24-35`)에 240분·일봉 위주의 장세 인식 계열(REGIME_BREAKOUT N=50 등)을 정식 전략 계열로 등록합니다. 지금은 스크립트 어댑터(`scripts/lib/regime-forward-candidate.js`)에만 있습니다.
- 2일 홀드아웃은 느린 규칙에 너무 짧으므로, 느린 계열에는 계열별 창 길이(예: 학습 180일, 검증 60일, 홀드아웃 60일)를 둡니다. 자격 기준(`researchFactoryQualification.ts`의 PBO 0.5, 비용 2배 양수 등)은 그대로입니다.

A2. **전진 검증 연결** (승인된 범위 안)
- 10-14에 시작한 전진 검증(`scripts/forward-regime-breakout.js`, 결과는 빨라야 2026-12-13)을 Research 서비스 타이머에 연결해 결과가 자동으로 쌓이게 합니다. 통과해도 "정식 실험 자격"일 뿐 승격 증거가 아닙니다.

A3. **승격 다리** (자격 통과 후보가 생길 때만)
- 자격을 통과한 후보만 `PromotionBridge` 기록과 도전자 바인딩(`paperChallengerBindingLedger`)을 거쳐 PAPER에 올립니다. 그때부터 학습 주기가 셉니다. 후보가 없으면 0/7은 정직하게 그대로 둡니다.

A4. **기준선 수수료 출혈 줄이기** (소유자 승인 필요: 전략 변경)
- 선택지: 기준선을 그대로 둘지, 기준선을 60분봉으로 바꿀지, 장세 필터(하락 신호에서는 진입 안 함)를 붙일지. 모두 PAPER 돈이라 실손은 없지만, 연속 손실 정지가 반복되면 관찰할 체결이 없습니다. 권장: 자격을 통과한 후보가 생길 때까지 **그대로 두고 관찰**만 합니다(근거 없는 전략 교체를 피함).

## 3. 설계 B: 바이낸스 선물 PAPER 도메인 (신규)
**왜**: 현물은 하락장에서 쉬는 것밖에 못 합니다. 선물(무기한)은 공매도로 하락 구간을 쓸 수 있어, 연구에서 확인된 "상승에서 벌고 하락에서 잃는" 문제를 정면으로 다룰 수 있습니다. 대신 레버리지·청산 위험이 있어 별도 안전 장치가 필요합니다.

**규칙**: `AGENTS.md`대로 Upbit 현물과 **완전히 분리된 도메인**입니다. 상태, 장부, 위험 게이트를 공유하지 않습니다. 공용 인터페이스만 같이 씁니다.

B0. **데이터 확보 확인 (먼저 해야 함)**
- 10-13 연구 기록에서 바이낸스 공개 API가 HTTP 451(지역 차단)을 돌려줬습니다(`WO-RESEARCH-20261013-ML-EXTERNAL.yaml:12`). PAPER 서버(Oracle)에서 공개 시세·마크 가격·펀딩비 조회가 되는지 읽기 전용으로 먼저 확인합니다. 안 되면 다른 공개 데이터원이나 저장된 과거 데이터로 연구만 하고, 실시간 PAPER는 보류합니다.
- 실거래나 국내 이용 가능 여부 같은 법적·약관 판단은 소유자 몫입니다. 이 설계는 PAPER만 다루므로 키와 계정이 필요 없습니다.

B1. **계약(contracts)**: `packages/contracts`에 선물 전용 타입: 포지션(롱/숏, 격리 마진), 마크 가격, 펀딩비(8시간), 청산 가격, reduce-only 주문, 레버리지.

B2. **시뮬레이터**: 선물 PAPER 체결 엔진(수수료, 슬리피지, 펀딩 정산, 마크 가격 기준 손익, 청산). 결정적이고 재시작해도 같은 결과(멱등)여야 합니다.

B3. **선물 위험 게이트** (소유자 승인 필요: 한도 숫자)
- 권장 초기값: 레버리지 최대 2배, 격리 마진만, 포지션당 증거금 상한, 청산 가격까지 거리 하한(예: 마크 가격의 25% 이상), 일일 손실 한도, 연속 손실 3. 이 한도는 현물 한도와 별개이며, 낮추는 방향으로만 바꿉니다.
- `ensemble-consensus-decision.md:107`이 요구한 증거금·마크 가격·펀딩·청산·reduce-only 게이트를 모두 통과해야 주문 의도가 실행됩니다.

B4. **연구**: 같은 사전 등록·홀드아웃 규칙으로 "장세 인식 롱/숏" 계열을 연구합니다. 펀딩비를 비용에 넣습니다.

B5. **섀도 → PAPER**: 섀도(가상 기록만)로 먼저 돌리고, 자격을 통과한 후보만 선물 PAPER에 올립니다.

B6. **화면**: 선물은 현물과 분명히 구분해 보여 줍니다(레버리지, 청산까지 거리, 펀딩비).

## 4. 설계 C: 소유자 화면 ("지금" 탭에 네 가지 답)
UX 원칙(`docs/NUSA_USER_EXPERIENCE_PRINCIPLE.md`)대로 "지금" 탭 맨 위에 한 문장 + 네 줄만 둡니다.
1. **오늘 손익**: 원화 금액과 % (현물, 나중에 선물 따로).
2. **왜 멈췄나**: 정지 사유 모델에 연속 손실 정지(예: "연속 3번 손실로 오늘 매수 쉼, 한국 시간 자정에 다시 시작")를 추가합니다. 지금은 "알 수 없음"으로 보입니다.
3. **배우고 있나**: 학습 0/7과 막힌 이유를 한 줄로("검증 통과 후보 없음, 전진 검증 12/13 결과").
4. **오토파일럿**: Worker 상태 한 줄(정상/대기/무료 모드).
- 테마 작업은 멈추고, 이 네 줄을 먼저 합니다. 작업 중인 CALM-REDESIGN 위에 얹습니다.

1. `state.yaml`의 지난 항목을 `.aipos/state-archive/`로 옮기고, 살아 있는 항목만 남깁니다(검증기 수정 필요).
2. 손으로 관리하는 지도 7개(`build-map`, `module-map`, `runtime-map` 등)와 중복 상태 파일 3개를 하나로 합칩니다.
3. 거의 같은 워크플로를 합칩니다: restricted-live 3개, Android 5개, 수렴·감시 5개, Cloudflare 4개.
4. Codex 워크플로 3개는 결정 4대로 꺼 둔 채 보관합니다(삭제 안 함).
5. 데스크톱 앱에 들어 있는 클라우드 연구 코드(`apps/desktop/src/cloud/*`)를 `apps/cloud`나 `packages`로 옮깁니다.
