# 실거래 관찰 · 선물 탭 설계 (설계만, 구현 전)

Safety stays: PAPER_ONLY, liveAuthority=NONE. 이 화면들은 보기 전용이며 어떤 주문·활성화 동작도 만들지 않는다.
"관찰" = 실거래가 열렸을 때 과정을 보고, 왜 그 전략을 썼는지 알 수 있는 것.

## 1. 실거래 탭 (이전 "안전")
- 위쪽 한 줄: 상태 한 단어 (잠김 / 준비 중 / 관찰 중). 지금은 "잠김 · 영구".
- 준비 관문: 표 대신 **관문 줄(gate line)** 하나. 관문 N개를 점 N개로 그리고, 통과한 점은 채워지고 막힌 점은 호박색.
  막힌 점이 천천히 숨 쉬듯 깜박이고(모션), 누르면 이유 한 줄. 숫자 "3 / 9"만 크게.
- 실거래 관찰(열렸을 때만 나타남, 지금은 "실거래가 열리면 여기서 볼 수 있어요" 한 줄):
  1. 타임라인: 판단 → 주문 → 체결 순서의 한 줄 흐름 (능선 그래프와 같은 시간축).
  2. 이유 카드: 각 주문마다 "왜" — 쓰인 전략, 신호 값, 통과한 위험 점검, 사용 한도.
     서버가 주문과 함께 reason 필드(전략 id, 신호, 점검 결과)를 남긴 것만 보여줌. 없으면 "이유 기록 없음"이라 표시, 짐작해서 채우지 않음.
  3. 모의와 나란히 비교(같은 시간 모의 결과).
- 서버 선행 작업: 주문 이벤트에 decisionReason 기록(표시용), 계약 검증기 추가.

## 2. 선물 탭 (이미 PR #2839, 시작 전 상태)
- 헤더: "선물 모의는 시작 전이에요 / 쉬고 있어요".
- 상태 → 포지션·손익 → 한도 사용량(일 손실, 청산 거리, 연속 손실 막대) → 고정 한도.
- 다음: 서버가 선물 스냅샷을 내려주면 입력 연결, 한도 막대는 한도에 가까울수록 호박색→적색.
- 실거래 탭과 같은 "이유 카드"를 선물 주문에도 재사용.

## 3. 순서
1) 이름 변경(완료) 2) 관문 줄 모션 3) 서버 reason 기록 4) 이유 카드·타임라인 5) 선물 서버 스냅샷 연결.
