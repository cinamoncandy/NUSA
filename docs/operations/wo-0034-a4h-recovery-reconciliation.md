# 복구 정산 및 소유자 검토 운영 가이드 (WO-0034-A4H / A4I)

앱을 재시작한 뒤 **"정산 확인이 필요합니다"**가 떴을 때 따라 하는 절차서입니다.
명령 단위로 적혀 있으니 위에서부터 그대로 하시면 됩니다.

---

## 0. 왜 이게 뜨는가

Shadow 관측을 하다가 앱이 꺼지면, 시스템은 **"꺼지기 직전 장부와 지금 장부가 같은지"**를 확인하기 전까지 다음 작업을 막습니다.

고장이 아닙니다. 확인 전에는 움직이지 않겠다는 뜻입니다.

이 확인은 **세 단계**이고, 각 단계는 앞 단계를 실제로 검사합니다:

```
① 대조  →  ② 소유자 승인  →  ③ 완료
   (자동)      (사람이 직접)      (둘 다 있어야)
```

**②는 반드시 사람이 화면에서 눌러야 합니다.** 명령줄로 승인하는 방법은 일부러 만들지 않았습니다.

---

## 1. 먼저 미리 보기 (앱 안 켜고)

앱을 켜기 전에, **지금 상태로 대조하면 어떤 결과가 나올지** 미리 볼 수 있습니다.
0.2초면 끝나고, 앱이 쓰는 것과 **똑같은 비교 함수**를 씁니다.

```bash
pnpm run build
node scripts/check-recovery-readiness.js --mark-price <현재 KRW-BTC 시세>
```

시세는 업비트 화면에서 보고 숫자만 넣으시면 됩니다. 예: `--mark-price 100000000`

**시세를 안 넣으면** 금액·수량 비교는 건너뛰고 그 사실을 알려줍니다. 없는 시세를 지어내지 않습니다.

### 나올 수 있는 결과

| 결과 | 뜻 | 다음 할 일 |
| --- | --- | --- |
| `MATCHED` | 장부가 일치 | 앱을 켜고 2번으로 |
| `MISMATCHED` | 막는 항목이 있음 | 아래 3번 표에서 해당 항목 처리 |
| `ERROR` | 비교 자체를 못 함 | 아래 4번 |

**이 도구는 아무것도 승인하지 않고, 아무것도 바꾸지 않습니다.** 저장소를 읽기 전용으로만 엽니다.

폴더를 직접 지정하려면:

```bash
node scripts/check-recovery-readiness.js --user-data "<앱 데이터 폴더>" --mark-price 100000000
```

Windows에서 앱 데이터 폴더는 보통 `%APPDATA%\dokkaebi` 입니다.

## 2. 앱에서 실제로 처리하기

```bash
pnpm run build
pnpm desktop
```

앱이 뜨면 **"복구 정산 및 소유자 검토"** 칸을 찾습니다 (안전진단 칸 바로 아래).

1. **"정산 대조 실행"** 을 누릅니다
2. 결과가 **일치**면 → **"소유자 검토 승인"** 이 켜집니다. 직접 누르십시오
3. 그다음 **"복구 완료 처리"** 를 누릅니다
4. "복구 게이트"가 **해제됨**으로 바뀌는지 확인합니다

**불일치나 대조 불가면 승인 버튼이 잠겨 있습니다.** 억지로 열 방법은 없습니다.

### 승인 후 상태가 바뀌면

"승인 유효성"에 **"무효 — 승인 후 상태가 바뀜"** 이 뜰 수 있습니다.

승인한 뒤에 무언가 달라졌다는 뜻입니다. 승인이 조용히 사라진 게 아니라, **그 승인은 바뀌기 전 상태에 대한 것이라 더 이상 쓸 수 없다**는 뜻입니다.
→ 대조부터 다시 하시면 됩니다.

## 3. 불일치 항목별 대처

| 코드 | 뜻 | 할 일 |
| --- | --- | --- |
| `KILL_SWITCH_ACTIVE` | 킬스위치가 켜져 있음 | 먼저 해제 |
| `UNRESOLVED_P0_ALERT` | 해결 안 된 최우선 경보 | 경보부터 처리 |
| `MARKERLESS_EVIDENCE` | 봉인 안 된 기록 폴더 | **지우지 말고** 다른 곳으로 옮기기 (아래 5번) |
| `CASH_MISMATCH` | 계산한 현금 ≠ 계좌 현금 | 금액 차이를 확인하고 보고 |
| `POSITION_MISMATCH` | 계산한 수량 ≠ 계좌 수량 | 수량 차이를 확인하고 보고 |
| `UNRESOLVED_FILLS` | 체결 기록 없는 주문 | 체결 기록 확인 |
| `PENDING_ORDERS` | 체결 시각이 확정 안 됨 | 주문 상태 확인 |
| `ORPHAN_ORDERS` | 식별번호 없는 주문 | 데이터 손상 가능 — 보고 |
| `LEDGER_INCONSISTENT` | 장부 자체가 안 맞음 | 보고 |
| `*_MUTATION` | 실제 거래 흔적이 있음 | **즉시 중단하고 보고** — Shadow의 전제가 깨진 것 |
| `PRIVATE_API_CAPABILITY_PRESENT` | 인증 거래소 기능 탐지 | **즉시 중단하고 보고** |
| `CREDENTIAL_CAPABILITY_PRESENT` | 자격증명 저장 기능 탐지 | **즉시 중단하고 보고** |

## 4. 대조 불가(ERROR)일 때

| 코드 | 뜻 |
| --- | --- |
| `PERSISTED_SNAPSHOT_MISSING` | 저장된 안전 스냅샷이 없음. 앱을 정상 종료한 적이 없을 수 있음 |
| `RECOVERY_RECORD_MISSING` | 복구할 대상 자체가 없음 |
| `ACCOUNT_STATE_UNREADABLE` | 계좌 상태를 못 읽음 |
| `MARK_PRICE_UNAVAILABLE` | 기준 시세가 없음 (미리보기에서 `--mark-price` 안 준 경우 정상) |
| `PERSISTENCE_UNHEALTHY` | 저장소를 못 엶 |
| `COMPARISON_THREW` | 비교 중 오류 |

**중요:** `ERROR`는 "문제가 없다"가 아니라 **"확인 자체를 못 했다"**입니다. 둘은 다릅니다.

---

## 5. 봉인 안 된 기록 폴더 처리

1. 앱을 완전히 종료합니다
2. 앱 데이터 폴더의 `shadow-evidence` 안에서 `completed.marker` 도 `aborted.marker` 도 **없는** 폴더를 찾습니다
3. 그 폴더를 **지우지 말고 옮깁니다** (예: 바탕화면의 `shadow-incomplete-백업`)
   - 지우면 그때 무슨 일이 있었는지 영영 알 수 없습니다
4. 앱을 다시 켭니다

---

## 6. 절대 하면 안 되는 것

- ❌ 복구 기록이나 증거 폴더 **삭제** (옮기는 건 됨)
- ❌ 불일치 상태에서 승인을 억지로 진행
- ❌ 대조 없이 완료 처리 시도
- ❌ 어떤 형태로든 업비트 API 키를 넣기
- ❌ 완료 전에 Shadow 관측 시작
