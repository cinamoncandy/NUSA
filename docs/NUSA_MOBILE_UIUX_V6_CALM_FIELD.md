# NUSA 모바일 UI/UX v6 — 새 설계 규격 (제안, 2026-11-25; 탭 구성은 현행 유지)

상태: **제안. 소유자 지시 "새로 다 만들어줘"의 첫 단계(설계).** 승인되면 v5(`docs/NUSA_MOBILE_UIUX_V5_OBSIDIAN_FINANCE.md`)를 대체한다. 근거: `docs/UIUX_DIAGNOSIS_2026-11-25.md`(코드 진단과 소유자 폰 캡처 3장). 화면 구현은 단계마다 draft PR, 독립 검토, 소유자 기기 확인을 거친다. PAPER_ONLY, `liveAuthority=NONE`, `productionMutationAllowed=false`, `aiAuthority=ZERO_AUTHORITY`. 이 문서는 어떤 권한, 한도, 게이트도 바꾸지 않는다. 표시 계층만 바꾼다.

## 1. 원칙
1. **정직이 먼저.** 없는 값은 만들지 않고, 값이 없으면 이유를 말한다. 설계상 정상인 상태(예: 수집 전용)는 경고색으로 보이지 않는다.
2. **한 사실은 한 번만.** 같은 상태를 한 화면에 두 번 쓰지 않는다. 안전 한 줄은 한 곳에 둔다.
3. **숫자가 먼저, 문장은 짧게.** 첫 화면 위 3분의 1에는 핵심 숫자 하나와 한 줄 설명을 둔다. 제목 문장은 두 줄, 화면 높이의 22% 이내.
4. **쉬운 말.** 소유자는 쉬운 한국어를 쓴다. 전문 용어는 한 번 풀어 쓴다.
5. **행동이 필요할 때만 색을 쓴다.** 주황은 "소유자가 할 일이 있다", 빨강은 "실제 손실 또는 차단"에만 쓴다. 정상이지만 쉬는 상태는 중립색.
6. **잠긴 것은 잠겼다고 말한다.** 실거래와 선물 탭은 **소유자 결정(2026-11-25 "지금 화면 그대로")으로 현재 위치에 그대로 둔다.** 대신 화면 안에서 "잠김 · 이유 · 열리는 조건"을 첫눈에 보이게 한다.

## 2. 정보 구조
하단 탭 **5개를 그대로 둔다**(소유자 결정, 2026-11-25 "지금 화면 그대로"): **지금 · 학습 · 실거래 · 선물 · 기록**. 탭 구성과 이름은 이 개편에서 바꾸지 않는다. (이전 제안인 4탭과 더보기 이동은 철회했다.)
- 상단 띠: 현재 모든 화면에 있는 안전 띠("수집 전용 · 주문 꺼짐 · PAPER 전용 · LIVE 잠김")는 **그대로 둔다.** 대신 같은 문장이 같은 화면에서 반복되지 않도록 `지금` 화면의 부제와 칩만 정리한다(단계 4, 소유자 확인).
- 하단 탭은 화면 흐름 안의 불투명한 띠이고 목록은 아래 여백을 이미 갖고 있다(캡처에서 잘려 보인 행은 스크롤 위치였다. `docs/UIUX_DIAGNOSIS_2026-11-25.md` 정정). 새 화면도 같은 여백 규칙(최소 32px)을 따른다.
- `실거래` 화면은 이미 "LIVE는 봉인되어 있습니다"와 남은 차단 조건을 보여 주고(`fieldScreensModel.ts`), `선물` 화면은 "시작 안 됨"을 정직하게 보여 준다. 열리는 조건 한 줄을 더할지는 소유자 확인 뒤에 정한다.

## 3. 화면 설계
### 3.1 지금
```
[수집 전용 · 주문 꺼짐]            (한 줄, 중립)
오늘 판단 0건                      (핵심 숫자, 큰 글씨)
주문 없이 지켜보는 중이에요        (한 줄 설명)
[격자 구 그래픽 — 소유자 결정 2026-11-25 "섬 대신 구"]  (서버 신호가 있을 때만 천천히 돈다)
연구 진행   체결흐름 9일 · 호가 대기 · …   (한 줄 요약, 탭하면 학습)
```
- 규칙: 칩, 부제, 띠에서 중복되는 문장을 제거한다. 그래픽(격자 구, 점 162개와 선 480개)은 실제 판단·주문·체결이 늘 때만 빛이 구 위로 퍼진다. 서버 값이 없으면 회색으로 멈춘다.

### 3.2 학습
```
수집 전용이라 판단은 쉬어요       (중립색. PAUSED가 정상일 때)
연구 N개가 데이터를 모으는 중      (한 줄)
─ 연구 일정 ─                      (서버가 내려 준 목록, 판정일 순)
  체결흐름 v2   11/29 · 데이터 9일
  S2~S4        12/05 · 설계 고정
  호가 3차      12/10 · 등록됨
  …
─ 학습 사슬 ─ 관찰 ● 신호 ○ 판단 ○ 안전 ○ 체결 ○ 평가 ○   (이유 한 줄)
─ 모의투자 성과 (기간: 2026-10-… ~ …) ─                    (기간을 항상 표시, 접힘 기본)
```
- 규칙: 상태 문구는 상태 코드와 실행 모드를 함께 보고 정한다(수집 전용이면 중립, 오류와 정지만 주황/빨강). 성과는 **기간 표시 없이는 보여 주지 않는다**. 연구 일정은 앱 코드에 박지 않고 서버 목록으로 받는다(단계 3).

### 3.3 기록
```
오늘 일어난 일  4
주문 기록 · 판단 기록 · 성과 · 자산        (행 4개, 제목과 한 줄 설명)
판단 규칙  2 → 전략 · 위험 한도
```
- 제목 "오늘의 로그"는 한 줄로 줄이고 목록을 위로 올린다.

### 3.4 실거래 · 선물 (자리 그대로)
맨 위에 "잠김 · 이유 · 열리는 조건" 한 줄. 아래는 지금 화면을 유지한다. 권한 값은 `PAPER_ONLY / LIVE NONE / productionMutationAllowed=false / ZERO_AUTHORITY`임을 표시만 한다.

## 4. 상태 → 표시 규칙 (핵심)
| 실행 상태 | 학습 제목 | 색 |
|---|---|---|
| 수집 전용 + 학습 `PAUSED` | "수집 전용이라 판단은 쉬어요" | 중립 |
| 정상 실행 | "모의투자로 배우는 중이에요" | 보통 |
| 위험 게이트 차단 | "안전이 막고 있어요" + 이유 | 주황 |
| 연결 없음 | "학습 정보를 받지 못했어요" + "빈 값은 결과가 없다는 뜻이 아니에요" | 주황 |
| 정지/오류 | "학습이 멈춰 있어요" / "오류가 있어요" + 이유 | 빨강 |

## 5. 토큰과 크기
기존 색과 글꼴 토큰(`designSystem.ts`, `visualSystem.ts`)을 쓰고 새 색을 만들지 않는다. 가로 여백 20px, 터치 영역 최소 48px, 본문 글자 최소 12px. 원색 값을 화면 모델에 쓰지 않는다(기존 시험이 막는다).

## 5.1 움직임, 오래된 데이터, 색 규칙 (디자인 시안 C안 기준)
- **움직임은 꺼질 수 있다.** 다이얼의 빛줄기와 점 깜빡임은 기기의 "동작 줄이기" 설정이 켜져 있으면 멈춘다. 움직여도 숫자와 글자는 움직이지 않는다.
- **움직임은 정상 관측의 증거일 때만 쓴다.** 서버 신호가 오래되면(최근 1분 기준 초과) 다이얼은 멈추고 "마지막 신호 n분 전"을 보여 준다. 멈춘 화면을 정상처럼 보이게 하지 않는다.
- **포인트 색은 한 가지, 뜻도 하나.** 포인트 색(시안의 청록)은 "정상으로 관측 중"일 때만 쓴다. 경고(주황)와 오류(빨강)는 4장의 표대로 따로 쓴다. 수집 전용 일시정지는 포인트 색도 경고색도 아닌 중립으로 둔다.
- **0은 거짓이 아니어야 한다.** `기록`의 0건 옆에는 이유("수집 전용이라 0건이 정상이에요")나 측정 기간을 붙인다. 이유를 알 수 없으면 "알 수 없어요"라고 쓴다.
- **시안의 막대와 숫자는 자리 표시다.** 24시간 신호 막대 등 시안의 값은 가짜다. 구현 때는 서버가 내려 주는 실제 기록으로 채우고, 없으면 그리지 않는다.
- 시안의 색 값(바탕 `#0d0f12`, 포인트 `#7ee7c7`)은 후보일 뿐이다. 5장대로 기존 토큰에 대응시키거나, 새 토큰이 필요하면 단계 4 전에 소유자가 정한다.

## 5.2 모션 사양 (구 그래픽, 시안 F안 기준; 수치는 코드 값과 시안 값을 구분해 적는다)
모든 움직임에 공통인 규칙은 5.1을 따른다. 아래 표의 "코드"는 `latticeSphereModel.ts` 등에 이미 있는 값이고, "시안"은 캔버스 시안에만 있어 아직 코드에 없는 값이다.

| 요소 | 언제 움직이나 | 수치 | 출처 |
|---|---|---|---|
| 구 회전 | 정상(NORMAL) 톤, 서버 값 있음, 동작 허용 | 초당 0.11 rad(한 바퀴 약 57초), 기울기 0.38 rad 고정 | 코드 |
| 판단 고리 | 실제 판단 수가 늘 때 | 하늘색 고리가 구 위로 퍼짐 2.6초, 한 번에 최대 8개, 320 ms 간격 | 코드 |
| 주문 고리 | 실제 모의 주문 수가 늘 때 | 판단 고리와 같고 분홍색 | 코드 |
| 체결 번쩍임 | 실제 체결 수가 늘 때 | 구 전체가 흰색으로 1.4초 | 코드 |
| 동작 줄이기 | 고리와 번쩍임이 움직이는 대신 | 시작점이 켜진 정지 장면 1.5초, 그 뒤 끔. 프레임 반복 없음 | 코드 |
| 프레임 | 회전 또는 고리가 있을 때만 | 약 30 fps, 앱이 백그라운드이면 멈춤 | 코드 |
| 궤도 위 빛 점 | 다음 판정이 있을 때 | 8초에 한 바퀴 | 시안 |
| 빛줄기 | 판단이 생긴 점에서 | 3.2초 주기로 밝아졌다 어두워짐 | 시안 |
| 점 지형 | 구 아래 바닥 | 시안은 5~7초 주기 물결. **권장: 평소에는 거의 정지하고 실제 판단이 생겼을 때만 빛이 한 번 지나감** | 시안 |
| 렌즈 고리, 세로 축 | 움직이지 않음 | 정지 | 시안 |
| 학습 구 | 움직이지 않음(한 자세) | 프레임 반복 없음 | 코드 |
| 기록 구석의 구 | 움직이지 않음 | `still`: 회전과 프레임 반복 없음(건강 신호가 없는 화면) | 코드 |

- **면적 규칙**: 화면에서 가장 넓은 면(바닥 지형)은 평소에 움직이지 않는다. 움직임은 작은 면(점, 고리)에 두고, 큰 면은 실제 사건이 있을 때만 한 번 반응한다.
- **수평 빛줄기는 쓰지 않는다**: 시안 초안에 있었으나 소유자가 거슬린다고 해서 뺐다(2026-11-25).
- **비용 규칙**: 점 수백 개를 매 프레임 개별로 그리지 않는다. 바닥 지형은 미리 만든 한 장의 그림을 쓰고, 구의 점은 깊이별 몇 묶음으로 그린다(코드는 이미 4묶음).
- **미확인**: 위 수치의 체감(속도, 번잡함)과 프레임 속도는 폰에서 본 적이 없다. 소유자 화면 녹화로 확인한 뒤 수치를 고친다.

## 6. 구현 단계 (모두 draft, 단계별 독립 검토와 소유자 기기 확인)
0. 소유자 확인: 완료(탭 5개 그대로, 2026-11-25). 상단 띠 반복 정리(단계 4)는 그때 다시 확인한다.
1. 표시 모델의 정직성 수정(모델과 시험만): 학습 제목의 수집 전용 중립 처리, 성과 기간 필드, 안전 띠 한 줄 규칙. 화면 변경 최소.
2. (정정으로 대부분 불필요) 목록 하단 여백은 이미 있다. `실거래`·`선물`의 "열리는 조건" 한 줄은 소유자 확인 뒤 선택 사항이다. 탭 구성은 바꾸지 않는다.
3. 서버가 연구 목록을 내려 주는 구조(클라우드 표시 전용 필드 + 앱 렌더링). 새 연구에 앱 빌드가 필요 없어진다.
4. `지금`, `학습`, `기록` 화면의 위계 재배치(숫자 우선, 제목 22% 이내). 소유자가 시안 C(관측소)를 거쳐 시안 E(격자 구)를 골랐다(2026-11-25, "섬 대신 구"). 조각별 draft PR: 4a #3299(큰 숫자와 0건 설명), 4b #3300(기록 타일), 4d #3302(지금의 섬을 구로 교체), 4e #3303(학습: 번호 붙은 구와 연구 번호), 4f #3304(기록 머리의 작은 구). 4c #3301(섬 둘레 눈금 고리)은 섬이 없어져 닫았다. 실거래·선물의 정지된 섬은 그대로다.
5. 정리: v5 문서와 안 쓰는 내비 모델 삭제 또는 이관.
각 단계는 **앱 빌드 배포가 아니라 draft PR**이고, 동결(2026-11-28 15:00 KST)과 호스트 릴리스 금지(2026-12-10까지)와 무관하다(앱은 호스트가 아니다). 앱 설치는 소유자 말씀과 기기 확인 뒤에만 한다.

## 7. 하지 않는 것
게이트, 임계값, 위험 한도, 자본, 권한 변경. 실거래 화면을 거짓 값으로 채우는 것. 탭 구성 변경(소유자가 "지금 화면 그대로"라고 정했다). 호스트 릴리스. 렌더링을 확인하지 못한 채 화면을 "완료"로 부르는 것(이 환경에는 기기 렌더링 수단이 없어, 화면 변경은 소유자 캡처 확인 전까지 "미확인"으로 적는다).
