# Autopilot 소유자 활동 게이트 설계 ("1시간 이상 코딩이 없을 때만 새 작업 시작")

상태: **설계 제안(기본값 적용)**. 코드·설정·권한 변경 없음 (`authority_impact: none`). 이 게이트는 오토파일럿이 하는 일을
**줄이기만** 하며 어떤 권한도 늘리지 않습니다. 구현은 이 문서가 승인된 뒤 별도 작업지시서로 진행합니다.

## 1. 목적과 기본값 (소유자 2026-10-12 채팅에서 기본값 승인)
- 소유자가 직접 코딩하는 동안 오토파일럿이 같은 파일·같은 PR을 건드려 충돌을 만들지 않게 합니다.
- **"코딩"의 기준**: 감시 대상(메인 Claude 쪽) 계정의 활동(푸시, PR 생성·갱신, PR 리뷰·댓글). 보조 Claude·자동화는 감시 대상과 분리된 계정을 쓴다는 전제입니다(§2).
- **막는 범위**: 새 코딩 작업의 시작만. 이미 시작한 작업은 끝냅니다(소유자가 다시 푸시해도 진행 중 작업은 계속함 — 소유자 결정).
- **조용한 시간**: 마지막 소유자 활동 후 60분(설정값).
- 막지 않는 것: CI, 결정적 Audit, 릴리스 봇의 병합, 배포, 상태 조회. 이들은 소유자 코딩과 충돌하지 않는 결정적 단계입니다.

## 2. 귀속 방식: 계정 분리 (소유자 결정 2026-10-12)
**역할 분담(소유자 결정)**: 소유자의 **메인 Claude(다른 Claude 계정)** 가 소유자가 직접 코딩하는 도구이고, **이 세션의 Claude는 보조**이며
오토파일럿과 같은 쪽입니다. GitHub에는 PR·커밋·댓글이 연결된 GitHub 계정의 이름으로 남으므로, 게이트가 구별하는 것은 Claude 계정이 아니라
**각 Claude에 연결된 GitHub 계정**입니다. 지금은 보조 세션도 소유자 계정(`cinamoncandy`)으로 올리고 있어 구별할 수 없습니다.

- **감시 대상 = 메인 Claude 쪽 GitHub 계정(`NUSA_AUTOPILOT_OWNER_LOGIN`)의 활동 전부.** 이름이 "OWNER"인 것은 "소유자가 코딩하는 쪽"이라는 뜻이며,
  실제 값은 메인 Claude가 GitHub에 올릴 때 쓰는 로그인입니다(소유자가 계정 분리 후 알려줄 값, 아직 확정되지 않음).
- 보조 Claude와 오토파일럿·Codex 자동화가 쓰는 GitHub 계정의 활동은 소유자 활동이 **아닙니다**. 커밋 메시지나 푸터 같은 귀속 표시는 해석하지 않습니다.

**이 방식이 성립하는 전제 (구현 전에 확인해야 할 것)**
1. 메인 Claude 쪽 GitHub 계정과 보조·오토파일럿 쪽 GitHub 계정이 **서로 다른 계정**이어야 합니다. 같으면 게이트가 구별하지 못해, 보조 작업이 "소유자가
   코딩 중"으로 읽혀 게이트가 닫힌 채 풀리지 않습니다.
2. 오토파일럿 Worker 토큰(`NUSA_GITHUB_TOKEN`), Codex 자동화 계정, 이 보조 세션이 **감시 대상 계정을 쓰지 않아야** 합니다.
3. 게이트는 Worker 토큰만 스스로 점검합니다. `GET /user`로 토큰의 계정을 읽어 **감시 대상 계정과 같으면 닫힘(설정 오류)** 으로 실패합니다.
   Codex 계정과 보조 세션의 계정은 이 점검으로 알 수 없으므로 소유자가 직접 확인해야 합니다.
4. 소유자가 메인 Claude가 아닌 다른 수단으로 감시 대상 계정으로 직접 푸시·댓글하면 그것도 사람 활동으로 읽힙니다. 설계대로입니다.

계정 분리가 끝나기 전까지는 게이트를 켜지 않습니다(소유자: 계정 분리는 2026-10-13에 진행). 켜지 않은 상태(현재)는 오토파일럿이 소유자 활동과 무관하게
동작하는 것과 같습니다.

## 3. 신호의 출처
- 저장소 이벤트 API(`GET /repos/{repo}/events`)에서 감시 대상 계정이 actor인 `PushEvent`, `PullRequestEvent`,
  `PullRequestReviewEvent`, `PullRequestReviewCommentEvent`, `IssueCommentEvent`를 읽습니다.
- 이 API는 지연(수 분)이 있고 보관 범위가 제한됩니다. 60분 창에는 충분하지만, **응답이 불완전하다고 볼 근거가 있으면**
  (오류, 가장 오래된 이벤트가 창 안에 있어 잘렸을 수 있는 경우 등) 활동 중으로 취급합니다.
- 이 신호는 **GitHub에 남는 활동만** 봅니다. 소유자가 로컬에서 코딩만 하고 아직 푸시하지 않았다면 게이트가 알 수 없습니다.
  이 한계는 수동 보류(§6)로 보완합니다.

## 4. 게이트가 걸리는 곳 (새 구조 없음)
새 코딩 작업이 시작되는 두 지점뿐입니다.
- Worker의 `POST /coding/propose`, `POST /coding/execute`(및 `index.ts`의 코딩 실행 처리) 입구에서, **실행 리스(lease)를 잡기 전에**
  게이트를 평가합니다.
- 게이트가 닫혀 있으면 새 응답 코드 `OWNER_ACTIVE`로 즉시 돌려보냅니다(리스를 잡지 않음, 코딩 엔진을 부르지 않음,
  유료 AI를 쓰지 않음). 열려 있으면 기존 흐름 그대로입니다.
- 실패 분류기(`codingRunnerFailureClass.ts`)에 `OWNER_ACTIVE`를 **대기(WAIT)** 로 추가합니다. 기다림은 재시도 예산(최대 3회)을
  소모하지 않고 실패로 세지 않으며, 완료 영수증에도 영향이 없습니다(제공자 용량 대기와 같은 취급).
- 기존 보류 장치(`EXPLICIT_HOLD` 등)는 PR 단위입니다. 새 게이트는 전역이고 시간 기반이라 **별도의 작은 순수 함수**
  `decideOwnerActivityGate(events, now, policy)`로 두고, 보류 장치를 확장하지 않습니다.

## 5. 설정과 실패 방향
- `NUSA_AUTOPILOT_OWNER_QUIET_MINUTES`(기본 60), `NUSA_AUTOPILOT_OWNER_LOGIN`(감시 대상 메인 계정). 배포 설정(`wrangler.jsonc`와 배포
  `--var`)에 값을 두고, 배포 테스트가 값의 존재를 요구합니다(#2631의 상한 설정과 같은 방식). 값이 없으면 안전한 쪽(게이트 닫힘)으로 실패합니다.
- 활동 조회 실패, 응답 형식 이상, 시계 이상은 모두 **닫힘(OWNER_ACTIVE)** 입니다. 게이트가 오작동해도 오토파일럿이 더 많이
  일하는 방향으로는 실패하지 않습니다.
- 게이트가 열린다는 것은 코딩 시작을 허용할 뿐입니다. 위험, 감사, 릴리스, 병합 권한과 무관합니다.

## 6. 수동 보류 (소유자 결정: 필요함)
로컬 코딩처럼 GitHub에 흔적이 안 남는 작업을 위해, 소유자가 직접 "지금부터 쉼"을 선언할 수 있어야 합니다.

- **명령**: 감시 대상 계정이 아무 이슈·PR에 남기는 댓글 한 줄 `/autopilot pause <N>h`(N은 1~24 정수)와 `/autopilot resume`.
  새 엔드포인트·새 저장소·새 권한 없이, §3에서 이미 읽는 저장소 이벤트(`IssueCommentEvent`)에서 함께 읽습니다.
- **엄격한 해석**: 댓글 본문이 정확히 위 형식일 때만 인정하고, **감시 대상 계정의 댓글만** 인정합니다(다른 계정 댓글은 무시).
  형식이 이상하거나 N이 범위 밖이면 보류 명령으로 보지 않습니다.
- **효과**: 가장 최근의 유효한 명령이 `pause`이면 `댓글 시각 + N시간`까지 게이트를 닫습니다. 더 최근의 `resume`이 있으면 해제합니다.
  보류는 60분 조용한 시간 규칙과 **별개로 합쳐집니다**(둘 중 하나라도 닫히면 닫힘).
- **자동 만료**: 최대 24시간입니다. 잊고 둬도 영원히 멈추지 않습니다. 더 오래 쉬려면 다시 `pause`를 남깁니다.
- **실패 방향**: 명령을 읽지 못하거나 이벤트가 잘렸을 가능성이 있으면 닫힘(§3)입니다. 즉 보류 상태가 불확실하면 쉬는 쪽으로 실패합니다.
- 기존 `GLOBAL_RELEASE_FREEZE`(배포 설정 기반 전체 동결)는 그대로 둡니다. 보류 명령은 새 코딩 작업 시작만 막고 릴리스·병합은 막지 않습니다.

## 7. 승인 기준 (구현 시)
- 수동 보류 테스트: 소유자 댓글만 인정, 형식·범위 오류는 무시, 가장 최근 명령이 우선, `resume` 해제, 24시간 만료, 60분 규칙과의 결합(둘 중 하나라도 닫히면 닫힘).
- 결정적 단위 테스트: 감시 대상 계정 활동은 창 안에서 닫힘, 다른 계정 활동은 무시, 정확히 60분 경계, 이벤트 누락·잘림·오류·시계 이상은 닫힘,
  설정 누락은 닫힘, Worker 토큰이 감시 대상 계정이면 닫힘.
- 게이트가 닫혔을 때 리스·코딩 엔진 호출·유료 호출이 모두 일어나지 않는다는 테스트, `OWNER_ACTIVE`가 재시도 예산을 쓰지 않는다는 테스트.
- 배포 설정 테스트(값 존재), 연결 안 된 함수 목록(`UNWIRED_CONTROL_PLANE_DEBT`)에 새 항목이 생기지 않음.

## 8. 결정 현황 (소유자)
1. 귀속 방식 → **결정됨: 계정 분리**(§2). 남은 확인: 메인 Claude 쪽 계정과 보조·오토파일럿 쪽 계정이 서로 다른지, 그리고 Worker 토큰·Codex 계정·보조 세션이 감시 대상 계정을 쓰지 않는지.
2. 수동 보류 → **결정됨: 필요함**(§6). 기본값: 댓글 명령 `/autopilot pause <1~24>h` / `resume`, 최대 24시간 자동 만료.
3. 소유자가 다시 푸시했을 때 → **결정됨: 진행 중이던 작업은 계속함**(§1). 새 작업 시작만 60분 조용한 시간 규칙으로 막습니다.

남은 열린 항목은 §6 기본값(최대 24시간, 댓글 명령 방식)을 소유자가 바꾸고 싶은지뿐입니다.

## 9. 한계 (정직한 범위)
- 설계이며 아직 아무것도 구현되지 않았습니다. 게이트 없는 지금의 오토파일럿은 소유자 활동과 무관하게 동작합니다.
- 소유자 로컬 작업과 대화형 AI 세션 활동은 GitHub에 흔적이 있어야만 보입니다.
- 계정 분리가 지켜지지 않으면(보조 쪽이 감시 대상 계정을 계속 쓰면) 게이트가 닫힌 채 풀리지 않습니다. Worker 토큰은 스스로 점검하지만 나머지는 소유자 확인이 필요합니다(§2).
