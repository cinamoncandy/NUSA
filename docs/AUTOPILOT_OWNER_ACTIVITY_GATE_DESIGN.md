# Autopilot 소유자 활동 게이트 설계 ("1시간 이상 코딩이 없을 때만 새 작업 시작")

상태: **설계 제안(기본값 적용)**. 코드·설정·권한 변경 없음 (`authority_impact: none`). 이 게이트는 오토파일럿이 하는 일을
**줄이기만** 하며 어떤 권한도 늘리지 않습니다. 구현은 이 문서가 승인된 뒤 별도 작업지시서로 진행합니다.

## 1. 목적과 기본값 (소유자 2026-10-12 채팅에서 기본값 승인)
- 소유자가 직접 코딩하는 동안 오토파일럿이 같은 파일·같은 PR을 건드려 충돌을 만들지 않게 합니다.
- **"코딩"의 기준**: 소유자 계정의 사람 활동(푸시, PR 생성·갱신, PR 리뷰·댓글). 
- **막는 범위**: 새 코딩 작업의 시작만. 이미 시작한 작업은 끝냅니다.
- **조용한 시간**: 마지막 소유자 활동 후 60분(설정값).
- 막지 않는 것: CI, 결정적 Audit, 릴리스 봇의 병합, 배포, 상태 조회. 이들은 소유자 코딩과 충돌하지 않는 결정적 단계입니다.

## 2. 가장 큰 위험: 소유자 계정과 AI 작업이 구별되지 않음
이 저장소의 PR·커밋·댓글은 AI 세션(Claude Code, Codex)도 **소유자 계정**으로 올립니다(PR 작성자가 모두 `cinamoncandy`).
계정만 보면 AI 활동이 "소유자가 코딩 중"으로 읽혀서 오토파일럿이 영원히 멈추거나, 반대로 AI 활동에 맞춰 열리는 문제가 생깁니다.

그래서 판단은 **계정이 아니라 귀속 표시(attribution)** 로 합니다.
- AI가 만든 커밋은 `Co-Authored-By: Claude …` 또는 `Claude-Session:` 줄, Codex 자동화 브랜치는 `autopilot/codex/`
  접두사를 가집니다. AI가 쓴 댓글에는 `Generated by [Claude Code]` 푸터가 있습니다.
- **소유자 활동 = 소유자 계정의 활동 중 AI 귀속 표시가 없는 것**.
- 이는 휴리스틱입니다. 사람이 AI 표시를 일부러 붙이거나 AI가 표시 없이 쓰면 틀립니다. 틀릴 때의 방향이 중요합니다.
  - 활동을 **AI로 오인**하면 게이트가 열려 오토파일럿이 소유자 코딩과 겹칠 수 있습니다(기존 상태와 같은 위험).
  - 판단이 불확실하면(표시를 읽지 못함 등) **활동 중으로 취급**해 멈춥니다.

## 3. 신호의 출처
- 저장소 이벤트 API(`GET /repos/{repo}/events`)에서 소유자 계정의 `PushEvent`, `PullRequestEvent`,
  `PullRequestReviewEvent`, `PullRequestReviewCommentEvent`, `IssueCommentEvent`를 읽습니다. 푸시는 head 커밋 메시지로,
  댓글은 본문 푸터로 AI 귀속 여부를 가립니다.
- 이 API는 지연(수 분)이 있고 보관 범위가 제한됩니다. 60분 창에는 충분하지만, **응답이 불완전하다고 볼 근거가 있으면**
  (오류, 빈 응답이 의심스러운 경우, 가장 오래된 이벤트가 창 안에 있어 잘렸을 수 있는 경우) 활동 중으로 취급합니다.
- 이 신호는 **GitHub에 남는 활동만** 봅니다. 소유자가 로컬에서 코딩만 하고 아직 푸시하지 않았다면 게이트가 알 수 없습니다.
  이 한계는 수동 보류(§6)로 보완합니다.

## 4. 게이트가 걸리는 곳 (새 구조 없음)
새 코딩 작업이 시작되는 두 지점뿐입니다.
- Worker의 `POST /coding/propose`, `POST /coding/execute`(및 `index.ts`의 코딩 실행 처리) 입구에서, **실행 리스(lease)를 잡기 전에**
  게이트를 평가합니다.
- 게이트가 닫혀 있으면 새 응답 코드 `OWNER_ACTIVE`로 즉시 돌려보냅니다(리스를 잡지 않음, 코딩 엔진을 부르지 않음,
  유료 AI를 쓰지 않음). 열려 있으면 기존 흐름 그대로입니다.
- 실패 분류기(`codingRunnerFailureClass.ts`)에 `OWNER_ACTIVE`를 **대기(WAIT)** 로 추가합니다. 기다림은 재시도 예산(최대 3회)을
  소모하지 않고 실패로 세지 않으며, 완료 영수증에도 영향이 없습니다(제공자 용량 대기와 같은 취급).
- 기존 보류 장치(`EXPLICIT_HOLD` 등)는 PR 단위입니다. 새 게이트는 전역이고 시간 기반이라 **별도의 작은 순수 함수**
  `decideOwnerActivityGate(events, now, policy)`로 두고, 보류 장치를 확장하지 않습니다.

## 5. 설정과 실패 방향
- `NUSA_AUTOPILOT_OWNER_QUIET_MINUTES`(기본 60), `NUSA_AUTOPILOT_OWNER_LOGIN`(소유자 계정). 배포 설정(`wrangler.jsonc`와 배포
  `--var`)에 값을 두고, 배포 테스트가 값의 존재를 요구합니다(#2631의 상한 설정과 같은 방식). 값이 없으면 안전한 쪽(게이트 닫힘)으로 실패합니다.
- 활동 조회 실패, 응답 형식 이상, 시계 이상은 모두 **닫힘(OWNER_ACTIVE)** 입니다. 게이트가 오작동해도 오토파일럿이 더 많이
  일하는 방향으로는 실패하지 않습니다.
- 게이트가 열린다는 것은 코딩 시작을 허용할 뿐입니다. 위험, 감사, 릴리스, 병합 권한과 무관합니다.

## 6. 수동 보류와 즉시 정지
- 소유자는 기존 `GLOBAL_RELEASE_FREEZE`로 언제든 전체를 멈출 수 있습니다. 로컬 코딩처럼 GitHub에 안 보이는 작업 전에는 이 방법을 씁니다.
- 별도의 "지금부터 N시간 쉼" 수동 보류는 이 설계에 넣지 않았고, 필요하면 후속 결정으로 둡니다.

## 7. 승인 기준 (구현 시)
- 결정적 단위 테스트: AI 귀속 푸시·댓글은 무시, 사람 활동은 창 안에서 닫힘, 정확히 60분 경계, 이벤트 누락·잘림·오류·시계 이상은 닫힘,
  설정 누락은 닫힘.
- 게이트가 닫혔을 때 리스·코딩 엔진 호출·유료 호출이 모두 일어나지 않는다는 테스트, `OWNER_ACTIVE`가 재시도 예산을 쓰지 않는다는 테스트.
- 배포 설정 테스트(값 존재), 연결 안 된 함수 목록(`UNWIRED_CONTROL_PLANE_DEBT`)에 새 항목이 생기지 않음.

## 8. 열린 결정 (소유자)
1. 귀속 표시 규칙을 위 목록(Claude 트레일러, Codex 브랜치 접두사, Claude 푸터)으로 충분히 볼지, 다른 AI 도구의 표시도 넣을지.
2. 소유자가 "쉼"을 선언하는 수동 보류가 필요한지.
3. 소유자가 다시 푸시했을 때 진행 중이던 작업을 계속 두는 기본값(§1)을 유지할지.

## 9. 한계 (정직한 범위)
- 설계이며 아직 아무것도 구현되지 않았습니다. 게이트 없는 지금의 오토파일럿은 소유자 활동과 무관하게 동작합니다.
- 소유자 로컬 작업과 대화형 AI 세션 활동은 GitHub에 흔적이 있어야만 보입니다.
- 귀속 표시 판단은 휴리스틱이라 완전하지 않습니다(§2). 불확실하면 닫힘으로 실패하도록 설계했습니다.
