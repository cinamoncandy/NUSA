# NUSA 실거래 연동 안전 가이드

⚠️ **중요**: 이 문서는 저장소 README의 "실거래 미지원, API 키 미저장" 원칙을 의도적으로 변경하는 작업의 안전장치를 규정합니다. 실제 자금이 걸린 영역이므로, 속도보다 **안전장치를 항상 우선**합니다.

## 0. 시작 전 확정할 것

### 코드 아키텍처 분리 원칙
- **PAPER 모드와 LIVE 모드는 코드 레벨에서 완전히 분리**한다
- 같은 함수/컴포넌트를 조건문으로 나누지 말 것 — 별도 모듈로 분리
- 목적: 실수로 모의투자 화면에서 실거래 주문이 나가는 사고 원천 차단

### 시각적 명시성
- 화면 어디서든 **지금이 PAPER인지 LIVE인지 색상+문구로 항상 명확히 표시**
- LIVE 모드: 화면 전체에 빨간 테두리, 경고문구
- PAPER 모드: 현재의 중립색 유지
- 상태 전환 시 사용자 확인 필수

## 1. 업비트 API 키 발급 (사용자 본인이 수행)

### 발급 절차
1. 업비트 웹사이트 → 마이페이지 → Open API 관리에서 키 발급
2. **권한을 최소로 제한**: 처음엔 "자산 조회"만 허용하고 "주문하기"는 꺼둔 채로 테스트
3. IP 화이트리스트 기능이 있다면 반드시 사용 중인 IP만 등록
4. 정기적으로 키를 재발급하고 이전 키는 즉시 폐기

## 2. API 키 저장 — 절대 코드/평문 저장 금지

### 저장 방식
API 키/시크릿은 **OS 자격 증명 저장소를 통해서만 저장**:
- **macOS**: Keychain
- **Windows**: Credential Manager
- **Linux**: Secret Service / pass
- **Electron**: `keytar` 라이브러리로 OS 계층에 접근

### 금지 사항
❌ `.env` 파일에 평문 저장
❌ 설정 JSON에 저장
❌ SQLite 데이터베이스에 저장
❌ 로그 또는 에러 메시지에 노출
❌ 개발자 도구 콘솔에 출력

### 검증 체크리스트
```
API 키가 로그나 에러 메시지, 개발자 도구 콘솔에 노출되는
경로가 있는지 코드 전체에서 검색하여 확인할 것.
```

## 3. 실거래 실행 전 다단계 안전장치

### 3.1 명시적 이중 확인
- **LIVE 모드에서 주문 버튼 클릭 시**: 바로 실행하지 말고 "실제 자금 ₩X로 매수/매도합니다" 확인창을 한 번 더 띄우기
- **PAPER 모드에는 없던 절차** — 명확한 차이 강조
- 확인창에는 주문 내용, 예상 수수료, 현재 시장가를 모두 표시

### 3.2 일일 손실 한도 (Kill Switch)
```
하루 손실이 사용자가 설정한 한도를 넘으면:
- 그날은 자동으로 LIVE 주문을 막고 PAPER로 강제 전환
- 사용자에게 경고 알림 표시
- 다음 날 자동 복구 (사용자가 명시적으로 재활성화 필요)
```

### 3.3 주문 금액 상한선
- 1회 주문 최대 금액을 설정값으로 제한
- 코드에서 이 상한을 우회할 수 없게 **서버/클라이언트 양쪽에서 검증**
- 상한선 초과 주문은 거부, 로깅 (공격/버그 탐지)

### 3.4 레이트 리밋
- 짧은 시간 내 반복 주문(오작동/버그로 인한 연속 주문) 감지 시 자동 정지
- 예: 5초 내 3회 이상 주문 → 잠금, 관리자 확인 필요

## 4. 단계적 전환 — 한 번에 켜지 않는다

### 1단계: 자산 조회만 (위험도 ⭐)
- API 권한: 자산 조회만 허용
- 기능: LIVE 잔고를 화면에 표시 (주문 기능 없음)
- 검증 기간: 며칠간 안정성 확인
- 목표: 키 저장/검증, 잔고 조회 API 동작 확인

### 2단계: 소액 실주문 테스트 (위험도 ⭐⭐)
- API 권한: 주문하기 추가 허용
- 기능: 아주 작은 금액(예: 1만원 단위)으로 실주문
- 검증: 매수/매도/취소가 의도대로 동작하는지 확인
- 목표: 실제 거래 프로세스 검증

### 3단계: AI 자동화 연동 (위험도 ⭐⭐⭐)
- **전제**: 이전 지시서(자기검증 루프)에서 다룬 AI 신호가 검증됨
- **원칙**: LIVE 모드에서는 AI 신호를 절대 자동 실행하지 않음
- **강제**: 항상 사람이 수동으로 확인하고 실행
- **대비**: PAPER에서는 자동 실행 허용, LIVE는 별개 규칙

### 4단계: 정상 거래 확대 (위험도 ⭐⭐⭐⭐)
- 안전장치 모두 검증됨
- 사용자가 설정한 한도 내에서 거래
- 정기적인 감시 (일일 손실 한도, 레이트 리밋)

```typescript
});

// 주문 금액 상한을 넘는 요청이 거부되는지
test("order amount limit rejects oversized orders", () => {
  // 상한선 x2 금액으로 주문 시도
  // 검증: 거부됨, 사용자 알림
});

// API 키가 어떤 경로로도 로그에 남지 않는지
test("API credentials never exposed in logs", () => {
  // 모든 로그/에러 메시지 검증
  // API 키 또는 비밀이 나타나면 실패
});

// PAPER/LIVE 모드가 실제로 분리되어 있는지
test("PAPER and LIVE modes are completely isolated", () => {
  // 같은 주문 로직을 PAPER/LIVE에서 실행
  // 결과가 완전히 독립적인지 검증
  // 한쪽의 버그가 다른 쪽에 영향 없음

// 이중 확인 절차가 동작하는지
test("LIVE mode requires explicit double confirmation", () => {
  // 주문 시도 → 확인창 표시 → 취소 선택
  // 검증: 주문 취소됨
  // 주문 시도 → 확인창 표시 → 확인 선택
  // 검증: 주문 실행됨
});

// 레이트 리밋이 동작하는지
test("rate limit blocks rapid successive orders", () => {
  // 5초 내 3회 이상 주문 시도
  // 검증: 3번째부터 거부, 잠금 상태
});
```

## 8. 비상 절차 (Go/No-Go)

### LIVE 모드 즉시 비활성화 신호
- API 키 유출 가능성
- 버그로 인한 비정상 주문 감지

### 비활성화 절차
```
1. LIVE 모드 즉시 OFF
2. 진행 중인 주문 모두 취소
3. 현재 포지션 로깅
4. 원인 분석 (로그 검토)
```
