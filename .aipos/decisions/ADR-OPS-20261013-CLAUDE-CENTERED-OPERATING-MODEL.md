# Claude-centered operating model (ACCEPTED 2026-10-14, revision 2)

Status: ACCEPTED by the owner on 2026-10-14 (decisions below); previously PROPOSED. Owner request 2026-10-13: move from a ChatGPT/Codex-centered process to a Claude-centered one and redesign the whole operating model while recording it in AIPOS. Revision 2 follows the owner's request to re-review the proposal; its facts were re-verified against the repository, the GitHub API and the Worker's public status between 22:00 and 22:40 UTC on 2026-10-12.

Decision proposed: keep every safety invariant, the deterministic control plane ("rules decide, AI repairs"), deterministic Audit and the release bot unchanged. Keep the governing charter's role names (OWNER, CORE, EVOLVE, AUTOPILOT, VALIDATOR, RESEARCH) and change only who fills them: CORE is a main Claude working on the owner's GitHub account; VALIDATOR and RESEARCH, plus operations, are an assistant Claude that moves to a single machine account used only for automated work; AUTOPILOT stays the Worker with Workers AI, limited to 150 changed lines in one file. AIPOS and work orders stay vendor-neutral.

Independence: a PR that changes code or workflows is reviewed under `docs/GRILL_ME_PROTOCOL.md` by the role that did not write it, in a fresh session. Documentation-only `authority_impact: none` PRs use the AGENTS.md lightweight path. Blocking findings are inline review threads, which the release workflow already refuses to merge past. Code PRs open as drafts until the review is done, because deterministic Audit skips drafts and HOLD PRs while green PRs otherwise merge within minutes (#2649 merged 7 minutes after it opened, #2643 after 8). Reviews are not verdicts and AI never submits an Approve review. Separate GitHub accounts are for attribution and the owner-activity gate, not a condition of independence.

Work claiming: push a branch named after the work order before starting (no workflow runs on non-main branch pushes) and search open PRs and branches first. `claimed_by` in `state.yaml` (revision 1) is withdrawn because a claim there is invisible until merged and the file conflicts on almost every PR.

Required before re-enabling Codex coding or enabling the owner-activity gate: (1) Autopilot repairs only failures of the canonical CI workflow and explicitly allowed workflows, never control-plane workflows; (2) a persistent per-failed-run attempt cap; (3) expected stops (gate closed, provider wait, repository mismatch) end as quiet NO_ACTION, ideally decided before dispatch; (4) the Worker's GitHub token moves off the owner's account to a new GitHub App (separate from the release-authority app) or the machine account. The PR #2644 implementation currently returns `OWNER_ACTIVE` as `FAILED_CLOSED`, which the execution consumer turns into a failed run, so it must be fixed first.

Rationale (verified): on 2026-10-12 UTC the Autopilot Execution Consumer failed 230 times (26 on 2026-10-11). The Worker's scheduled runtime treats any failed non-repository_dispatch run on the main head within 24 hours as a repair target (`apps/autopilot/src/scheduledRuntime.ts:216`), so it re-dispatched a repair for the failed Codex coding run 38300571241 eleven times between 19:55 and 20:48 UTC, about every 5 minutes, and stopped only on the WIP limit and a new main head; a PAPER evidence workflow failure (run 38287517884) was also selected. During the temporary Dokkebi rename every dispatch failed on repository mismatch. The consumer exits non-zero on `FAILED_CLOSED` (`scripts/autopilot-dispatch-retry.js:1337`) and its runs are triggered as `cinamoncandy`, so failure notifications reach the owner. Two more failures followed at 22:06 and 22:11 UTC after the Codex workflow was disabled. All of the last 60 PRs, including Autopilot Codex PRs, are authored by `cinamoncandy`. The Codex review bot only posts usage-limit comments. Paid GitHub Models overflow (`openai/gpt-4.1`) has no daily cap until #2631 merges. Main protection requires `nusa/release-authorized` (app 4935691) with enforcement `everyone`.

GitHub terms allow one free personal account and one free machine account per person, the latter used exclusively for automated tasks; the identity plan follows that.

Alternatives considered: requiring different GitHub accounts for review independence (rejected: not achievable before P0 and not what independence needs); `state.yaml` claims (rejected, above); Claude as the Autopilot engine (deferred: paid API, needs an owner budget and cap); automatic Claude review on every PR through Claude Code GitHub Actions or Code Review (owner decision: needs a repository secret, usage and the Claude GitHub App's broad permissions).

Migration: P0 owner identity and settings, P1 Autopilot repair-target allowlist, attempt cap and quiet stops (can start before P0 with owner approval), P2 operating documents (`CLAUDE.md`, `AGENTS.md`, master instructions merge wording, claim and review rules), P3 HOLD and stale PR triage (45 open, 34 created before October; close only on an owner-approved list, never delete branches), P4 engine and cost, P5 Codex assets. Details and the six owner decisions: `docs/CLAUDE_CENTERED_OPERATING_MODEL.md`.

Not changed: PAPER_ONLY, liveAuthority=NONE, productionMutationAllowed=false, aiAuthority=ZERO_AUTHORITY, risk limits (consecutive-loss limit 3), Audit and Release authority, AIPOS vendor neutrality, owner shortcuts.

## Owner decisions (2026-10-14, in chat; recorded under WO-OPS-20261014-CLAUDE-CENTERED-DECISIONS)
1. Roles, independence rule and work flow: adopted. Design moves from ChatGPT to Claude. `CLAUDE.md`, `AGENTS.md` and the master instructions may be updated in a separate P2 documentation PR.
2. Identity (revised the same day): keep the current repository and account setup; the Worker keeps its current token and no machine account is created. A new GitHub App (never the release-authority app) is created only if needed later. Consequence: Worker failure notifications still reach the owner, and the owner-activity gate (#2644) stays off because Autopilot activity cannot be told apart from the owner's.
3. Engine and cost: Workers AI stays. The paid GPT-4.1 overflow is turned off (option b); the #2631 daily cap is not needed for it.
4. Codex: the coding workflow, manual runner and review bot stay disabled and are kept, not removed.
5. Cleanup order: the recommended P3 order is followed. #2644 is enabled only after it is fixed; stale PRs are closed only from an owner-approved list; branches are never deleted.
6. Automatic review: on request only.

None of these decisions changes LIVE, risk, capital or AI authority: PAPER_ONLY, liveAuthority=NONE, productionMutationAllowed=false, aiAuthority=ZERO_AUTHORITY.
